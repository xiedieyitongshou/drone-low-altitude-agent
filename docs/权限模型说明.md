# 权限模型说明

本文档说明 `user_id`、`tenant_id`、`role`、`visibility` 在历史、Trace、规则集、知识库和任务单中的边界。

## 核心原则

- 后端 token 是当前用户身份的唯一可信来源。
- `/agent/query` 不信任前端传入的 `user_id`。
- 普通用户只能访问自己的历史、会话、Profile、Trace 和任务单。
- 管理员可以访问用户治理、系统统计和全局会话审计能力。
- RAG 检索必须按 `visibility`、`tenant_id`、`user_id` 和 metadata 过滤。
- fallback 不能绕过权限校验。

## 身份字段

| 字段 | 含义 | 使用位置 |
|---|---|---|
| `user_id` | 当前登录用户 ID | 历史、会话、Profile、Trace、任务单、用户私有知识 |
| `tenant_id` | 租户或组织边界 | 知识库、规则集、后续多租户数据隔离 |
| `role` | 用户角色 | 普通用户接口、管理员接口、前端菜单展示 |
| `visibility` | 数据可见性 | 知识库、规则集、共享数据与私有数据过滤 |

## 登录与鉴权

认证入口：

- `POST /auth/register`
- `POST /auth/login`

后端通过 JWT 解析当前用户，并在依赖层注入请求上下文。业务接口不应相信前端提交的用户身份字段。

## 历史与会话

普通用户边界：

- 只能查看自己的对话历史。
- 只能查看自己的评估记录。
- 只能使用自己的 Profile Memory。
- 多轮 pending task 按 session 和用户隔离。

管理员边界：

- 可以查看全局会话审计。
- 可以做用户治理和系统统计。
- 不应通过普通用户接口绕过审计路径访问其他用户数据。

## Trace

Trace 用于解释 Agent 执行链路，也属于用户数据。普通用户只能查看自己的 trace；管理员可通过审计接口查看全局 trace 或会话链路。

Trace 需要保留：

- plan
- tool_call
- tool_result
- error
- fallback
- final_response

权限边界：

- trace 查询按当前 token 用户过滤。
- 工具失败和 fallback 记录不能泄露其他用户数据。
- 管理员审计接口需要单独的 role 校验。

## 知识库与 RAG

知识库可见性由 `visibility`、`tenant_id`、`user_id` 和 metadata 共同决定。

典型边界：

- 公共知识：所有授权用户可检索。
- 租户知识：同一 `tenant_id` 范围内可检索。
- 用户私有知识：仅所属 `user_id` 可检索。
- 管理员知识管理：允许管理全局知识，但仍应记录审计边界。

RAG 空召回或低置信时返回保守提示，不编造政策依据，也不能通过 fallback 扩大检索范围。

## 规则集

规则集可以按可见性和租户边界管理。普通用户只应使用自己有权限访问的规则集；管理员可以管理全局或租户级规则配置。

## 任务单

任务单属于业务状态数据，应按当前用户隔离。任务条件修改、状态重算和执行记录都应绑定当前 token 用户。

边界：

- 普通用户只能查看和修改自己的任务单。
- 管理员如需跨用户查看，应走管理员审计或管理接口。
- Agent 多轮修改任务单时必须继承当前用户上下文。
