# 知识发布进程退出恢复验收

日期：2026-11-27。工作目录：`D:/desktop/drone-low-altitude-agent`。

## 问题与修改

原发布逻辑先提交数据库中的 `success` 和 `index_dirty=false`，再切换索引指针。已用临时 SQLite 和 `os._exit()` 复现：进程退出后，新检索进程仍读取旧版，但数据库显示发布成功。

修改后，发布任务持久保存候选版本和阶段，候选 manifest 保存文档修订及构建时的限制状态。先切换索引指针、处理限制，再提交成功状态及相符文档的发布标记。

启动、每次发布前以及存活进程每 60 秒执行对账，均使用同一跨进程构建锁。指针已切换则校验并补齐数据库；未切换则中断任务失败、待发布状态保留，不自动续发候选。数据库收尾错误可以重试，已完成恢复可重复检查。

## 覆盖场景

`tests/test_knowledge_publication_recovery.py` 共 32 个参数展开后的用例，覆盖：

- 真实子进程在构建中、构建完成、ready、publishing、切换前、切换后、限制处理后、最终提交前后共 9 个位置执行 `os._exit(71)`。
- 根据实际指针对账，重复恢复不改变已完成结果；持锁的正常发布不会被误判为退出。
- 应用启动完成恢复后才提供服务；存活进程的周期检查能恢复另一个进程的中断任务。
- 最终数据库提交失败、指针替换后抛错，以及恢复时数据库暂时失败后的重试。
- 后续内容编辑仍待发布；恢复前或恢复中的新撤回、暂停保持有效；解除限制不会重新开放旧版本。
- 控制文件写入失败保守保留限制并提示重新发布。
- 索引文件缺失、摘要不符、上下文缺失、manifest 丢失及非对象 JSON 被拒绝，不猜测切换或回滚指针。
- 升级前的最新成功任务与实际指针矛盾时保守恢复待发布；正常历史成功记录保留；旧候选源丢失时保守恢复所有文档的待发布标记。
- 同一 metadata 恢复用例在 SQLite 和 PostgreSQL 独立 schema 中验证，条件更新保留文档修订时间。

## 部署与边界

新增数据库迁移 `e3b7a9d20c64`，只增加可空的 `index_version`、`publication_phase` 两列。默认启动迁移可应用；关闭启动迁移时须先运行 `python -m alembic upgrade head`。旧任务的两个字段保持 NULL，供兼容恢复判断。

索引目录、控制文件和锁必须由同一实例的所有进程共享。恢复不自动发布未生效的候选，不删除旧版本，不自动恢复全局暂停。当前指针本身指向损坏版本时只记录校验错误，需检查文件或重新发布。

本次验证针对进程退出及本地持久化状态，不代表真实模型效果、生产部署结果或宿主机断电后的灾难恢复。此次只修改工作区代码、测试及说明，未部署服务。
