# 建单请求幂等性

2026-11-23：`POST /tasks` 和 `POST /agent/query` 接收可选的 `Idempotency-Key` 请求头。它标识一次提交意图，不代表一段文本或一类任务。旧客户端不传键时保持原有行为，每次调用仍可新建任务。

## 请求约定

- 键为 1–128 位字母、数字、`.`、`_`、`:`、`-`；前端使用 UUID。
- 当前登录用户来自 token。同一用户、同一操作类型、同一键受数据库唯一约束保护。
- 同键、同内容返回首次成功响应快照；任务后续被修改或取消，不会改变这份快照。读取当前状态仍使用任务详情接口。
- 同键、不同内容返回 HTTP 409，`error_code=IDEMPOTENCY_KEY_REUSED`。任务内容由请求模型校验、补齐默认值后计算摘要，JSON 对象键顺序不影响摘要。
- 新键代表新的意图，即使内容相同也允许新建。相同键可以由不同用户独立使用。
- 客户端超时、断网、未确认处理结果时必须保留原键。收到成功响应后才结束该操作；主动新建使用新键。

前端在用户和操作范围内，用 `sessionStorage` 保存尚未确认的操作 ID 和请求。刷新后恢复最近一条未确认输入，重新提交会复用原键。浏览器存储不可用时仅保留当前页面内存副本；清除站点数据或关闭标签页后不保证恢复。编辑后发起不同请求会创建新操作，先前未确认请求的键仍保留，回到原输入可继续重试。

## 事务与恢复

`operation_requests` 保存请求摘要、首次请求、成功结果。`task.create` 的占位记录、任务插入和响应快照在同一数据库事务提交。并发请求由唯一约束仲裁：后到的插入等待先到事务结束，再读取已提交结果。提交前失败同时回滚任务与记录；提交成功后连接或响应中断，重试读取已保存结果。

Agent 使用 `agent.query` 记录原始 `query` 与 `session_id`，在解析之前验证和回放；不信任请求体里的 `user_id`。成功响应和追问响应可以回放，临时失败允许原键重试。每次新的追问补充使用新键。

Agent 建单工具使用稳定的父操作记录 ID 作为 `agent.task.create` 的键。子记录和任务原子提交。即使进程在建单后、完整回复保存前中断，后续重试也先寻找已提交的子记录，使用冻结的任务与参数恢复结果，不重新解释“明天”、用户偏好或会话条件。恢复未完成的响应不会回写可能已经变化的会话上下文。

PostgreSQL 使用跨事务的操作咨询锁防止同一 Agent 操作重叠执行，锁冲突返回 HTTP 409、`IDEMPOTENCY_IN_PROGRESS`，客户端保留原键稍后重试。进程退出或连接断开会释放锁。SQLite 的 Agent 执行保护限于同进程；任务插入的唯一约束仍由 SQLite 数据库保证。现有会话锁继续按用户和会话工作。

操作记录没有自动短期过期策略，避免旧键失效后重新建单。其生命周期应与业务重试与任务保留策略一起管理。
