# 本地开发与测试说明

本文档集中说明本地启动、依赖、环境变量、后端测试、前端构建、Eval 快速集和完整评测命令。Docker 运行见 [Docker部署说明.md](Docker部署说明.md)，CI 运行见 [CI-CD说明.md](CI-CD说明.md)。

## 前置依赖

- Python 3.11
- Node.js 与 npm
- Docker 与 Docker Compose
- 和风天气 API Key
- 可选：DeepSeek / OpenAI 兼容 API Key，用于 LLM 结构化解析

## 后端本地启动

在项目根目录执行：

```powershell
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
docker compose up -d --wait postgres redis
.\.venv\Scripts\activate
python -m pip install -r requirements.txt
python -m uvicorn main:app --reload
```

后端启动时会自动检查数据库版本并补齐尚未执行的迁移；版本已是最新时直接启动，不会重复建表或重置数据。`python main.py` 和 `python -m uvicorn main:app --reload` 均使用同一启动检查。迁移失败时后端不会进入就绪状态。默认启用；由部署流程单独管理迁移时可设 `AUTO_MIGRATE_ON_STARTUP=false`。

后端默认地址：

```text
http://localhost:8000
```

Docker 后端已经占用 8000 端口时，可给本机的 Uvicorn 命令加 `--port 8001`。两个后端仍可连接同一个数据库。

常用入口：

```text
http://localhost:8000/health
http://localhost:8000/docs
```

## 核心环境变量

基础配置：

```env
APP_ENV=local
APP_PORT=8000
CORS_ALLOWED_ORIGINS=http://localhost:5173,http://127.0.0.1:5173
DATABASE_URL=
POSTGRES_DB=drone_agent
POSTGRES_USER=drone_agent
POSTGRES_PASSWORD=change-me-postgres-password
JWT_SECRET_KEY=replace-with-random-secret
SESSION_MEMORY_BACKEND=database
SESSION_MEMORY_TTL_SECONDS=
ANONYMOUS_SESSION_TTL_SECONDS=1800
REDIS_URL=redis://localhost:6379/0
```

- `DATABASE_URL` 留空时，应用根据 `POSTGRES_DB`、`POSTGRES_USER` 和 `POSTGRES_PASSWORD` 连接 PostgreSQL。本机默认地址为 `127.0.0.1:5432`，可用 `POSTGRES_HOST` 和 `POSTGRES_PORT` 覆盖；Compose 应用和工具容器使用 `postgres:5432`。本机与 Compose 可以共用同一个库。
- 要切回 SQLite，将 `DATABASE_URL` 设为 `sqlite:///./data/drone_agent.db`，然后重启使用该配置的后端。本机使用 SQLite 时可以直接执行 Alembic 和 Uvicorn 命令。
- 要使用外部数据库，可以把完整连接串填入 `DATABASE_URL`。同一份 `.env` 用于本机和容器时，连接串中的地址应当对两边都可达。
- 切换连接配置后，按需单独迁移历史数据。[迁移步骤](Docker部署说明.md#7-sqlite-到-postgresql-迁移)

登录后的 `/agent/query` 默认把最新上下文按 `user_id` 和 `session_id` 写入 PostgreSQL 的 `session_records`。上下文在最后一次写入 30 天后失效，服务启动时及之后每隔 24 小时清理过期行。聊天历史、任务和评估结果各自保存在业务表中。可以用 `SESSION_MEMORY_TTL_SECONDS` 调整数据库会话的有效期，测试可通过 `SESSION_MEMORY_BACKEND=ttlcache` 使用进程内缓存。

免登录的 `/nl/parse` 在提供 `session_id` 时使用 Redis，上下文从最后一次写入起默认保留 30 分钟，可通过 `ANONYMOUS_SESSION_TTL_SECONDS` 调整。继续已有会话时使用同一个 `session_id`。

天气服务配置：

```env
QWEATHER_API_KEY=your_qweather_api_key
QWEATHER_GEO_BASE_URL=https://geoapi.qweather.com
QWEATHER_WEATHER_BASE_URL=https://devapi.qweather.com
QWEATHER_WARNING_BASE_URL=https://devapi.qweather.com
```

LLM 默认关闭：

```env
LLM_ENABLED=false
NL_PARSER_MODE=rule
```

需要启用 DeepSeek 结构化解析时：

```env
LLM_ENABLED=true
LLM_PROVIDER=deepseek
LLM_MODEL=deepseek-v4-flash
DEEPSEEK_API_KEY=your_deepseek_api_key
NL_PARSER_MODE=hybrid
```

Agent Runtime 建议默认使用：

```env
AGENT_RUNTIME_MODE=loop
```

```powershell

.\.venv\Scripts\python.exe scripts/failure_recovery_eval.py
```

覆盖重点：

- Tool Calling：意图识别、工具选择、参数组装。
- Multi-turn State：状态继承、字段覆盖、session 隔离、上下文污染。
- Failure Recovery：参数缺失、外部依赖失败、fallback、权限绕过。

## RAG Eval

当前仓库报告采用 2026-11-20 原始验收结果，于 11 月 22 日同步入库；本次文档更新不以新运行替换它。[当前 RAG 链路与结果](RAG检索与无答案处理说明.md) · [报告来源](../evals/reports/README.md)

以后需要重新生成时运行：

```powershell
$env:LLM_ENABLED = 'false'
$env:RAG_CONFIDENCE_THRESHOLD = '0.2'
.\.venv\Scripts\python.exe scripts/rag_eval.py
```

该命令覆盖 `evals/reports/rag_eval.*`；保留历史结果时追加 `--report-dir data/eval-reports/rag-new-run`。pytest 中的 `run_eval()` 不写报告。当前 11 个案例按检索器分别执行 9/10/10/11 条，共 40 次；Embedding 为本地 Mock，原有语料的 Agent 回放与合成夹具 Eval 分开统计。

覆盖重点：

- Recall@K
- Hit@K
- Metadata filter
- 权限泄露率
- 低置信 fallback
- P95 延迟

生成报告目录：

```text
evals/reports/
```

## 会话可靠性故障验证

独立于现有开发服务，使用专用 Compose 启动两实例、真实 PostgreSQL/Redis 和内部天气 HTTP 夹具，验证重启、过期、存储不可用、并发及后置写入故障。

```powershell
docker build -t drone-low-altitude-agent:session-reliability-validation .
python scripts/session_reliability_eval.py --repeats 3
```

运行结束自动清理测试项目的容器和专属数据卷，原始 JSON 和日志保存在 `data/eval-reports/session-reliability/`。场景定义、指标分母和复跑说明见 [验证说明](会话可靠性验证说明.md)，实际结果与留档证据见 [实测报告](会话可靠性实测报告.md)。该故障套件尚未接入 CI。

## 本地排查顺序

- 启动失败：先检查 `.env`、`DATABASE_URL`、Alembic migration、端口占用。
- 天气失败：检查 `QWEATHER_API_KEY` 和三个 QWeather base URL。
- 登录失败：检查 `JWT_SECRET_KEY`、用户表 migration、管理员初始化。
- Agent 行为异常：检查 `NL_PARSER_MODE`、`AGENT_RUNTIME_MODE`、Trace 事件和 Eval 报告。
- RAG 结果异常：检查知识库路径、索引文件、metadata filter 和 `RAG_CONFIDENCE_THRESHOLD`。
