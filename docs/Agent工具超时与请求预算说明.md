# Agent 工具超时与请求预算说明

## 本次改动范围

本次复用已有的操作 ID、请求回执、建单恢复和任务版本检查，增加执行期间的截止时间与提交检查。没有重新实现工具幂等，也没有数据库结构迁移。

- `POST /agent/query` 从进入编排器开始计时，覆盖 legacy 和 loop 两种模式，以及解析、外部请求、重试退避、业务持久化和响应整理。鉴权及 HTTP 传输不在这段应用处理预算内。
- 所有通过 `ToolRegistry.call` 调用的工具都执行 `ToolSpec.timeout_ms`，包括旧流程直接调用注册表的路径。默认工具时限仍为 30 秒。
- 工具使用请求剩余预算和工具自身时限中较早的截止时间，重试不会重置截止时间。
- 直接调用 `/tasks` 等结构化接口仍沿用原有行为；它们不是本次新增整轮 Agent 预算的入口。

## 配置

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| `AGENT_REQUEST_TIMEOUT_MS` | `45000` | 一轮 Agent 应用处理的总预算，单位毫秒 |
| `AGENT_REQUEST_WORKERS` | `4` | 每进程同时运行的 Agent 编排任务上限 |
| `AGENT_TOOL_WORKERS` | `4` | 每进程同时运行的工具任务上限 |

总预算中预留最多 250ms（小预算时为其 10%）记录超时诊断，不额外延长请求预算。容量上限是资源保护配置，不是实测吞吐量；调整时需要同时考虑数据库连接数。

本地配置见 `.env.example`，Docker 后端通过 `docker-compose.yml` 注入这些参数。前端默认 HTTP 等待上限为 60 秒，后端默认处理预算为 45 秒。

## 执行与状态一致性

1. 编排和工具使用不同的有界工作池，避免编排占满线程后等待同一池中的工具。没有无限排队；容量不足时返回 `EXECUTION_CAPACITY_EXCEEDED`。
2. 超时返回 `TOOL_TIMEOUT` 或 `REQUEST_DEADLINE_EXCEEDED`。正在运行的 Python 线程不被强制终止，容量槽在它实际退出后才释放。持续阻塞的工具会占用容量，后续调用得到繁忙响应。
3. 每个执行单元自行创建和关闭数据库 Session，只在线程间传递 Engine 与普通输入数据。提交前必须没有尚未提交的调用方修改；绑定共享事务 Connection 的 Session 不能传入后台执行。
4. 同一预算通过执行上下文传递给 LLM、天气请求和解析重试。每次外部请求使用配置上限和剩余预算的较小值；退避也可被预算耗尽或取消打断。HTTP 客户端各阶段超时之外，外层截止时间负责限制调用方等待总时长。
5. 在受预算控制的执行中，SQLAlchemy 的 `before_flush`、`before_commit` 检查预算和取消状态；PostgreSQL 每次事务设置不超过剩余预算的 `statement_timeout` 与 `lock_timeout`。TTLCache、Redis 会话修改也检查预算。
6. 超时后不能开始新的业务提交。已经进入数据库提交的操作可能完成，不能把超时一律解释为“没有写入”；建单的任务和回执仍原子提交，相同操作 ID 重试可恢复原结果。
7. 任务版本检查继续生效。工具启动后不会切回旧流程重放，超时结果不登记为成功回执，也不覆盖成功会话上下文。
8. 后台工具的 Trace 和计时使用独立缓冲，只有按时返回的结果才合并，迟到工具不能修改已经返回请求的 Trace 或计时栈。
9. 多地点比较的内部线程继承同一个预算，各自记录计时；最多同时提交四个地点分支，超时后不再启动后续地点。

## 验收覆盖

`tests/test_tool_executor.py` 验证慢工具在自身时限到达时提前返回，并确认后台尚未结束。

`tests/test_execution_budget.py` 使用隔离数据库、事件控制和模拟时钟覆盖：

- 超时后迟到创建不能落库，执行线程的 Session 与调用方不同；
- 迟到任务更新在 flush 前或 commit 前被拒绝，原任务内容和版本保持不变；
- 工具已提交但返回超时，原有操作回执可以恢复且不重复建单；
- 连续超时期间仍运行的线程继续占用容量，不产生无限工作队列；
- 解析与工具共享预算，解析过期后不能启动工具；
- 整轮在建单提交后超时，使用相同操作 ID 恢复，跳过解析并复用结果；
- 天气连续超时、退避耗尽总预算，以及重试次数先耗尽；
- LLM 请求使用剩余预算，解析预算耗尽后不再重试或退回规则解析；
- 迟到工具不能修改父请求的 Trace 与计时。
- 多地点并发分支共享预算、独立计时，过期后不再启动更多地点。

完整回归继续检查已有任务版本、建单幂等、会话隔离和历史关联。PostgreSQL API 测试改用独立 schema，允许后台独立连接读取真实提交，同时避免共享事务连接；专项测试加入 PostgreSQL CI 门禁。
