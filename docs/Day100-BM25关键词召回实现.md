# Day100 BM25 关键词召回实现

Day100 的目标是在 Day99 Retriever 抽象基础上新增 BM25 关键词召回，同时保留 TF-IDF baseline。

## 为什么不删除 TF-IDF

TF-IDF 继续保留为 baseline，原因是：

- 后续 RAG Eval 需要和 BM25、Embedding、Hybrid 做效果对比
- Day102 Hybrid Retrieval 需要多个检索器并存
- 保留 baseline 能证明检索增强是可评估的，而不是直接替换算法

当前默认检索器可通过环境变量控制：

```text
KNOWLEDGE_RETRIEVER=bm25
KNOWLEDGE_RETRIEVER=tfidf
```

默认值为 `bm25`。未知值会回退到 `tfidf`。

## BM25 索引是什么

这里的索引不是数据库索引，而是 BM25 检索所需的预处理数据。

BM25 索引包含：

- 文档 token 列表
- 每篇文档的词频 `tf`
- 每篇文档长度 `doc_length`
- 平均文档长度 `avg_doc_length`
- 每个词的文档频率 `df`
- 每个词的 `idf`

索引文件：

```text
data/knowledge/index/bm25_index.pkl
data/knowledge/index/bm25_documents.json
```

它不能直接复用 TF-IDF 的 `tfidf_vectorizer.pkl` 和 `tfidf_matrix.pkl`，因为 TF-IDF 保存的是向量矩阵，BM25 需要原始词频、文档长度和 IDF。

## 知识库结构是否需要重建

不需要修改 `data/knowledge/advice_rules.json`。

当前 BM25 复用 Day67-Day70 已经完成的数据治理字段：

- `knowledge_type`
- `region`
- `province`
- `city`
- `visibility`
- `tenant_id`
- `user_id`
- `version`
- `effective_at`
- `expires_at`
- `review_status`

BM25 只是基于同一份知识库生成自己的本地索引。

## 分词策略

当前不引入额外分词依赖，使用轻量 tokenizer：

- 英文、数字、下划线作为连续 token
- 中文生成单字、bigram、trigram
- 文档标题、正文、metadata 关键词共同参与索引

这样可以覆盖：

- `深圳`
- `管制空域`
- `实名登记`
- `禁飞区`
- `inspection`
- `policy_hint`

## 检索流程

```text
KnowledgeRetrievalRequest
  ↓
build_knowledge_retrieval_query
  ↓
Bm25KnowledgeRetriever
  ↓
LocalBm25KnowledgeStore
  ↓
metadata filter
  ↓
BM25 score
  ↓
RetrievedKnowledgeSnippet
```

metadata filter 仍然是前置条件：

- 用户不可见的文档不参与返回
- 不匹配任务类型、风险标签、地域、审核状态和时效的文档不参与返回

## 当前代码落点

- `app/services/bm25_knowledge_store.py`：BM25 索引构建、分词、召回和评分
- `app/services/knowledge_retrievers.py`：新增 `Bm25KnowledgeRetriever`，并支持 `KNOWLEDGE_RETRIEVER` 切换
- `app/services/vector_knowledge_store.py`：提取公共 `build_indexed_documents`
- `tests/test_bm25_knowledge_store.py`：BM25 关键词召回、权限过滤、检索器切换测试
