# 真实 DeepSeek 回归验收方案

更新日期：2026-11-27。入口：[deepseek_regression_eval.py](../scripts/deepseek_regression_eval.py)。场景：[test_deepseek_regression.py](../tests/test_deepseek_regression.py)。

本组验证 DeepSeek 接入后，任务参数、工具调用、会话续接、数据库状态和最终规则结果是否一致。当前已完成场景实现及离线模型夹具验证，真实模型验收尚未完成，不能引用离线结果作为 DeepSeek 的准确率或性能结论。

## 1. 模型与程序的职责

```text
自然语言与隔离会话上下文
  → DeepSeek 返回结构化意图和参数
  → Schema 校验与上下文处理
  → Planner 选择工具
  → ToolExecutor / Guardrail
  → 实际业务工具与临时数据库
  → 规则结论、任务状态、响应与逐项断言
```

这组回归测试的是现有 LLM 解析入口。工具选择由程序 Planner 完成，业务结论由规则引擎生成；不能将其称为已验证模型自主规划或原生 Function Calling。解释生成和知识相关性复核的模型调用在本组关闭。

## 2. 测试隔离

| 项目 | 测试配置 |
|---|---|
| 天气 | 固定本地 provider 响应：完整逐小时晴天、低风、无降水和明确无预警；不请求外部天气供应商 |
| 数据库 | 子进程启动前指定临时 SQLite，忽略业务数据库配置，结束后清理 |
| 用户和会话 | 每类场景使用独立合成用户及数据库 Session |
| 业务执行 | 调用实际 Orchestrator、实际 Tool Registry handler、状态与快照服务 |
| 模型 | 任务解析请求访问指定 DeepSeek 模型；不以模拟响应作为 live 通过证据 |
| 故障 | 先确认收到非空模型响应，再受控替换为无效 JSON 或非法字段；报告标明注入类型 |

该环境验证服务调用链路，未包含浏览器页面或实际天气网络链路；PostgreSQL/Redis 故障可靠性属于独立专项。

## 3. 五类场景与验收项

| 类别 | 操作 | 必须满足的断言 |
|---|---|---|
| 缺参续接 | 给日期、时段和巡检类型但不给地点，再补充深圳 | 首轮只追问地点，不执行工具/天气；续接后工具使用正确地点并继承日期、时段和类型；返回固定天气下的预期结论 |
| 修改条件 | 深圳巡检改为广州、换时段和测绘类型，保留日期 | 新值覆盖旧值；日期保留；实际天气查询和最终请求使用新地点；重新得到正确逐小时结果 |
| 任务操作 | 建单、相同操作 ID 重试、评估、推荐、选窗、复核 | 重试不增加任务或再次调用模型；各操作引用同一任务；数据库状态和响应一致，版本递增；推荐有窗口，最终复核结论被保存 |
| 格式与字段异常 | 在 `llm` 模式分别注入无效 JSON、非法日期字段 | 返回结构化追问/失败，不执行工具或天气，不产生评估记录；记录两种注入，而非只验证返回文字 |
| 规则回退 | `hybrid` 下收到模型响应后注入格式错误 | 来源为 `llm_fallback_rule`；规则解析、实际工具和最终业务结果正确；此例作为恢复能力，不计算为模型自然输出正确 |

前三类是正常场景，后两类是受控故障。正常场景不能用静默规则回退冒充模型解析成功。

## 4. 指标分层

### 已作为硬断言的指标

| 指标 | 判定 |
|---|---|
| 五类执行完整性 | 五类均执行并形成报告，不能以默认跳过替代 |
| 场景通过率 | 五类均通过该类全部检查；一类内有多个轮次和操作，不把它称为五个独立自然语言样本 |
| 模型响应证据 | 每个实际解析调用收到非空响应；不可用或空响应必须使该场景失败 |
| 正常路径来源 | 正常工具成功响应须为 `parser_source=llm` 且运行状态完成 |
| 工具正确性 | 仅出现目标工具、工具成功；按场景核对关键参数及任务引用 |
| 状态和写入 | 会话字段继承/覆盖正确；任务状态与版本和数据库一致；同一操作重试不重复建单 |
| 最终评估 | 地点、日期、时段、任务类型及固定天气下的规则结论一致，有逐小时结果 |
| 异常路径安全 | 格式或字段错误不执行不完整请求、不写入评估；hybrid 回退来源和结果可核对 |

### 已采集、用于分析的指标

- 每次模型调用尝试的耗时、是否收到响应、注入类型；失败和空响应也保留尝试记录。
- 调用尝试数与非空响应数分别统计；建单幂等重试不应新增模型调用。
- `model_attempt_latency_ms` 记录样本数、最小值、中位数和最大值，包含失败尝试，不默认设模型延迟阈值。
- 响应中的 `agent_runtime.timings` 保留处理阶段耗时；其范围不等于浏览器端到端延迟或所有数据库提交耗时。

当前不独立计算通用语料上的意图准确率、所有字段准确率、长期成功率和价格成本。Token/费用还未采集；模型延迟 SLA、重复运行次数与波动阈值需积累真实数据后另行确定，不能填入估计值冒充实测。

## 5. 如何执行

确保已明确允许把合成请求及会话上下文发送给模型供应商，并在进程环境或本机文件中配置待测模型与凭据。不要把凭据写进样例或报告。

```powershell
.\.venv\Scripts\python.exe scripts/deepseek_regression_eval.py --env-file .env
```

可用 `--model` 选择模型，用 `--report-dir` 指定报告根目录。未指定环境文件时从进程环境读取 `LLM_MODEL` 及 `LLM_API_KEY`/`DEEPSEEK_API_KEY`。每次报告使用独立 `run_id`。

GitHub Actions 仅在手动 `workflow_dispatch` 勾选 `run_deepseek` 后执行；模型来自 `deepseek_model` 或 `DEEPSEEK_EVAL_MODEL`，凭据来自 secret `DEEPSEEK_API_KEY`。Push/PR 不触发真实模型组。

## 6. 证据与退出条件

`data/eval-reports/deepseek/<run_id>/` 包含：

- `summary.json`：代码提交、工作区状态、模型、端点、隔离条件、五类结果、模型响应数与尝试耗时摘要。
- `case-*.json`：模型响应、尝试记录、故障标记、逐轮工具实参、业务响应和断言结果。
- `junit.xml`：pytest 执行与错误信息。

缺少模型或凭据属于配置失败，退出 `2`；测试失败、未完整执行五类、没有收到所需模型响应或存在未通过断言时退出 `1`；全部验收通过才退出 `0`。

受控格式/字段异常应注明注入位置，不能把它计为供应商自然错误率。一次五类通过先建立功能基线，后续相同配置的重复运行再用于分析模型波动。对外保存证据前检查响应、端点和上下文，公开摘要不包含凭据或私有业务内容。
