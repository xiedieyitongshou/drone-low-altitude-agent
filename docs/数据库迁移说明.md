# 数据库迁移说明

本文档记录从 SQLite 文件库迁移到 PostgreSQL 的路径。项目当前默认使用 PostgreSQL，保留 SQLite 配置供显式切换。[当前迁移命令](Docker部署说明.md#7-sqlite-到-postgresql-迁移)

## Day156 压测背景

Day156 的私有演示环境当时使用 SQLite：

- Day156 线上轻量压测中，3 VU 下未发现 `SQLite database locked`。
- 写入类接口表现可接受，主要耗时来自 Agent/LLM 链路，不是数据库。
- 当前服务器规格较低，PostgreSQL 可以同机部署验证，但不应把它等同于高并发生产数据库方案。

## 当时评估的触发条件

满足任一条件时进入 PostgreSQL 迁移验证：

- 5 到 10 并发下，写入类接口稳定出现 `SQLite database locked`。
- Trace、Conversation History、任务单同时写入时，P95 长期超过 `3000 ms`，且 CPU/内存未满。
- 演示或试用并发需求超过 3 人，并且需要更稳定的多写入能力。
- 需要更正式的备份恢复、权限治理、连接池管理或长期公网服务。

如果瓶颈来自 LLM 限流、天气 API、SSH 隧道、前端加载或服务器 CPU/内存不足，不应直接归因到 SQLite，也不应直接通过迁移数据库解决。

## 拓扑选择

### 方案 A：同机 Docker Compose PostgreSQL

推荐作为当前阶段的迁移验证方案。

适用场景：

- 单机私有演示。
- 1 到 3 人低并发访问。
- 需要验证 SQLAlchemy/Alembic 对 PostgreSQL 的兼容性。
- 希望最小化运维成本。

优点：

- 成本最低。
- 部署路径和当前 Docker Compose 一致。
- 易于回滚到 SQLite。

风险：

- PostgreSQL 与 FastAPI、Redis、前端共享 2 核 2 GiB 机器资源。
- 系统盘 40 GiB，需要限制日志、备份和数据库增长。
- 不适合作为高并发或长期生产方案。

部署含义：

- PostgreSQL 运行在同一台服务器上的 Docker 容器中。
- 不建议通过 `apt`、`yum` 等方式把 PostgreSQL 直接安装到宿主机系统。
- 数据库进程由 Docker Compose 管理，数据通过 Docker volume 持久化到宿主机磁盘。
- SSH 隧道仍只需要转发前端 `5173` 和后端 `8000`；PostgreSQL 端口不需要暴露给本地浏览器。

建议低配参数：

```yaml
postgres:
  image: postgres:16-alpine
  container_name: drone-agent-postgres
  environment:
    POSTGRES_DB: drone_agent
    POSTGRES_USER: drone_agent
    POSTGRES_PASSWORD: ${POSTGRES_PASSWORD:?set-postgres-password}
  ports:
    - "127.0.0.1:5432:5432"
  volumes:
    - postgres_data:/var/lib/postgresql/data
  command:
    - "postgres"
    - "-c"
    - "shared_buffers=128MB"
    - "-c"
    - "effective_cache_size=512MB"
    - "-c"
    - "work_mem=4MB"
    - "-c"
    - "maintenance_work_mem=64MB"
    - "-c"
    - "max_connections=20"
  healthcheck:
    test: ["CMD-SHELL", "pg_isready -U drone_agent -d drone_agent"]
    interval: 10s
    timeout: 5s
    retries: 5
```

对应 volume：

```yaml
volumes:
  redis_data:
  postgres_data:
```

### PostgreSQL 数据存放位置

即使 PostgreSQL 运行在容器里，数据库文件最终仍保存在服务器宿主机磁盘上。容器内的数据目录是：

```text
/var/lib/postgresql/data
```

使用 Docker named volume 时：

```yaml
volumes:
  - postgres_data:/var/lib/postgresql/data
```

Docker 会把 `postgres_data` 映射到宿主机的 Docker volume 目录。通常路径类似：

```text
/var/lib/docker/volumes/<compose-project>_postgres_data/_data
```

实际路径应以 `docker volume inspect` 为准：

```bash
docker volume ls | grep postgres
docker volume inspect <volume-name>
```

推荐使用 named volume，而不是直接把 PostgreSQL 数据目录放进项目目录：

```text
推荐：postgres_data:/var/lib/postgresql/data
不推荐：./data/postgres:/var/lib/postgresql/data
```

原因：

- PostgreSQL 数据目录权限更少出问题。
- 不容易被误删、误同步或误提交。
- 与当前 Redis 的 `redis_data` 管理方式一致。
- 备份恢复应使用 `pg_dump`、`pg_restore` 或 `psql`，而不是手动复制正在运行中的数据目录。

如果为了演示环境可读性选择目录挂载，也可以使用：

```yaml
volumes:
  - ./data/postgres:/var/lib/postgresql/data
```

此时数据会落在服务器项目目录下：

```text
/opt/drone-low-altitude-agent/app/data/postgres
```

但该方式需要更谨慎地处理权限、备份和 `.gitignore`，因此不作为默认推荐方案。

### 方案 B：独立数据库服务器

适用场景：

- 后端服务仍在轻量 ECS 上，但数据库需要独立资源。
- 并发或数据量超过同机承载范围。
- 需要单独做数据库备份、监控、权限收敛。

优点：

- 应用和数据库资源隔离。
- 后续扩容更清晰。

风险：

- 多一台服务器，运维成本上升。
- 需要额外处理内网访问、安全组、备份和网络延迟。

### 方案 C：云厂商托管 PostgreSQL

适用场景：

- 准生产或生产环境。
- 需要自动备份、监控、故障恢复、权限管理。
- 不希望自行维护数据库实例。

优点：

- 可靠性和运维能力最好。
- 备份恢复、监控告警、参数管理更成熟。

风险：

- 成本最高。
- 需要处理云网络、安全组、白名单和连接数限制。

当前建议：

- Day157 阶段选择方案 A 作为迁移验证方案。
- 若并发需求超过 10 人或进入长期公网服务，再评估方案 B 或方案 C。

## 环境变量设计

显式选择 SQLite：

```env
DATABASE_URL=sqlite:///./data/drone_agent.db
```

默认 PostgreSQL 配置。本机默认连 `127.0.0.1:5432`，Compose 应用默认连 `postgres:5432`。

```env
DATABASE_URL=
POSTGRES_DB=drone_agent
POSTGRES_USER=drone_agent
POSTGRES_PASSWORD=<replace-with-strong-password>
```

如果应用容器连接宿主机上的 PostgreSQL，可使用宿主机或内网地址：

```env
DATABASE_URL=postgresql+psycopg://drone_agent:<password>@<host>:5432/drone_agent
```

约束：

- 不把真实密码提交 Git。
- 服务器真实 `.env` 只保存在服务器。
- PostgreSQL 端口默认只绑定 `127.0.0.1` 或 Docker 内网，不直接暴露公网。

## 依赖规划

当前 `requirements.txt` 已包含 PostgreSQL 驱动：

```text
psycopg[binary]>=3.2,<4.0
```

连接串使用：

```text
postgresql+psycopg://...
```

如果后续对镜像体积或构建可控性要求更高，可以从 `psycopg[binary]` 改为系统依赖加 `psycopg`，但当前演示环境优先选择安装简单、风险低的方式。

## 兼容性检查结论

已检查本地和服务器上的 `app/db/models`、`alembic/env.py`、`alembic/versions`。

未发现明显 SQLite 专属写法：

- 未使用 `sqlalchemy.dialects.sqlite`。
- 未使用 `PRAGMA`。
- 未使用 `WITHOUT ROWID`。
- 未使用 `INSERT OR REPLACE`。
- 未使用 `last_insert_rowid` 或 `rowid`。
- 未使用 SQLite 专用 `json_extract`、`json_each`、`strftime`、`julianday`。

现有模型主要使用 SQLAlchemy 通用类型：

- `String`
- `Text`
- `Integer`
- `Float`
- `Boolean`
- `DateTime`
- `JSON`
- `ForeignKey`
- `Index`
- `UniqueConstraint`

需要关注但不阻塞迁移的点：

- `app/db/session.py` 默认根据 `POSTGRES_*` 配置连接 PostgreSQL。显式设置的 `DATABASE_URL` 优先。
- `check_same_thread` 是 SQLite 专用连接参数，但代码已经只在 SQLite URL 下启用。
- 部分 migration 使用 `op.batch_alter_table`，这是为了兼容 SQLite 的 ALTER TABLE 限制，在 PostgreSQL 下可执行。
- `ee7f4c2b9a10_add_users_table_and_memory_user_links.py` 有一处 `SELECT DISTINCT user_id ...` 裸 SQL，语法同时兼容 SQLite 和 PostgreSQL；迁移时要校验旧数据是否满足用户外键和唯一约束。
- `DateTime(default=datetime.utcnow)` 是 Python 侧默认值，不是数据库 `server_default`；迁移后应用写入正常，但直接 SQL 插入需要显式提供时间字段。
- `JSON` 在 PostgreSQL 下会映射为 JSON 类型；导入历史 SQLite 数据时必须确认 JSON 字段内容是合法 JSON，而不是普通字符串。

## 迁移步骤

### 1. 停止写入

正式切换前需要停止用户访问或停止后端容器，避免迁移期间 SQLite 继续写入。

```bash
cd /opt/drone-low-altitude-agent/app
docker compose stop app frontend
```

Redis 可以保留运行。若希望完全冻结环境，也可以停止全部服务：

```bash
docker compose down
```

### 2. 备份 SQLite 和配置

```bash
BACKUP_DIR=/var/backups/drone-low-altitude-agent/pg-migration-$(date +%Y%m%d%H%M%S)
mkdir -p "$BACKUP_DIR"
cp -a data/drone_agent.db "$BACKUP_DIR/drone_agent.db"
cp -a .env "$BACKUP_DIR/env.backup"
docker compose config > "$BACKUP_DIR/docker-compose.resolved.yml"
sqlite3 data/drone_agent.db ".backup '$BACKUP_DIR/drone_agent.sqlite-backup.db'"
sqlite3 data/drone_agent.db "PRAGMA integrity_check;" > "$BACKUP_DIR/sqlite-integrity.txt"
```

### 3. 增加 PostgreSQL 服务

在服务器 Compose 文件中加入 `postgres` 服务和 `postgres_data` volume。

应用、工具容器和测试容器的 `DATABASE_URL` 改为：

```env
DATABASE_URL=postgresql+psycopg://drone_agent:<password>@postgres:5432/drone_agent
```

所有会执行 Alembic 或访问数据库的服务都要保持一致：

- `app`
- `admin-init`
- `knowledge-import`
- `knowledge-reindex`
- `backend-tests`
- `eval-fast`
- `eval-full`

### 4. 构建带 PostgreSQL 驱动的镜像

确认 `requirements.txt` 已包含 `psycopg[binary]` 后重新构建：

```bash
docker compose build app admin-init knowledge-import knowledge-reindex backend-tests eval-fast eval-full
```

### 5. 启动 PostgreSQL

```bash
docker compose up -d postgres
docker compose ps postgres
docker compose logs --tail=100 postgres
```

确认健康：

```bash
docker compose exec postgres pg_isready -U drone_agent -d drone_agent
```

### 6. 初始化 PostgreSQL schema

```bash
docker compose run --rm admin-init python -m alembic upgrade head
```

如果不希望同时创建管理员账号，可以临时直接运行：

```bash
docker compose run --rm app python -m alembic upgrade head
```

确认版本：

```bash
docker compose run --rm app python -m alembic current
```

### 7. 导入历史数据

推荐使用一次性脚本按表顺序导入，不直接复制 SQLite 文件。

导入顺序必须满足外键关系：

1. `locations`
2. `users`
3. `user_profiles`
4. `mission_tasks`
5. `task_requests`
6. `weather_provider_snapshots`
7. `weather_hourly_snapshots`
8. `weather_warning_snapshots`
9. `cruise_assessments`
10. `cruise_hourly_assessments`
11. `conversation_records`
12. `session_records`
13. `agent_trace_events`
14. `rule_sets`
15. `rule_items`
16. `knowledge_documents`
17. `knowledge_index_jobs`

导入注意事项：

- 保留原主键值，避免历史外键断裂。
- JSON 字段用 Python `json.loads` 校验后写入。
- Boolean 字段从 SQLite 的 `0/1` 转换为 `false/true`。
- DateTime 字段按 ISO 或 Python `datetime` 写入。
- 导入前禁用用户写入；导入后再开放访问。

如果没有历史数据保留要求，可以跳过导入，直接使用空 PostgreSQL schema，并重新执行管理员初始化和知识库导入。

## 回滚方案

回滚窗口建议至少保留 24 小时。窗口内不要删除 SQLite 备份、旧 `.env` 或 PostgreSQL volume。

触发回滚的条件：

- 应用启动失败。
- Alembic 迁移失败且无法快速修复。
- 数据导入后关键表记录数不一致。
- 登录、任务单、历史记录、Agent Trace 任一核心链路不可用。
- PostgreSQL 容器资源占用导致整机不稳定。

回滚步骤：

```bash
cd /opt/drone-low-altitude-agent/app
docker compose stop app frontend
cp -a /var/backups/drone-low-altitude-agent/<backup-dir>/env.backup .env
cp -a /var/backups/drone-low-altitude-agent/<backup-dir>/drone_agent.db data/drone_agent.db
chmod 600 data/drone_agent.db
docker compose up -d redis app frontend
curl -sS http://127.0.0.1:8000/health
```

如果 Compose 文件也改过，需要从备份恢复或手动移除 `postgres` 服务和 PostgreSQL `DATABASE_URL`。

回滚后保留 PostgreSQL volume 做问题分析，不要立即删除：

```bash
docker volume ls | grep postgres
```

## 风险清单

| 风险 | 影响 | 处理 |
|---|---|---|
| PostgreSQL 驱动缺失 | 应用无法启动 | 迁移前增加 `psycopg[binary]` 并重建镜像 |
| JSON 历史数据不合法 | 导入失败或查询异常 | 导入脚本逐字段 `json.loads` 校验 |
| Boolean 从 SQLite `0/1` 迁移 | 类型不匹配 | 导入时显式转换为 `bool` |
| 外键顺序错误 | 导入失败 | 按外键依赖顺序导入 |
| 同机资源不足 | 整机变慢或容器重启 | 限制 PostgreSQL 参数，观察 `docker stats` |
| PostgreSQL 端口暴露 | 数据库安全风险 | 只绑定 `127.0.0.1` 或 Docker 内网 |
| 数据迁移期间继续写入 | 两边数据不一致 | 迁移前停止后端或关闭访问入口 |
| 回滚窗口不足 | 故障后难以恢复 | 保留 SQLite、`.env`、Compose 备份至少 24 小时 |
