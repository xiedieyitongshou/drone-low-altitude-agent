# 架构设计说明

本文档汇总说明项目的主要架构关系。更细的阶段实现记录保留在各 `Dayxx-*.md` 文档中，本文只维护当前可运行版本的主链路。

## 总体定位

项目不是固定串行 workflow，而是面向低空作业场景的 AI Agent 工程原型。自然语言、LLM、RAG、Memory 和前端控制台用于增强交互和解释能力，最终适飞 / 慎飞 / 禁飞结论由确定性规则引擎输出。

核心边界：

- LLM 不直接给出飞行安全结论。
- RAG 不覆盖规则引擎结论。
- Agent Runtime 负责编排工具和状态，不替代业务服务。
- Guardrail 固定在输入、工具调用和最终输出阶段。
- Trace 记录关键执行事件，支撑审计和问题定位。

## 分层结构

```text
Browser / React Console
  -> Auth / Axios Client
  -> FastAPI API Layer
      -> Auth Dependency / User Scope
      -> Agent Orchestrator
          -> NL Parser: rule / llm / hybrid
          -> Context Manager: session + profile + pending task
          -> Business Route / Planner
          -> Tool Registry / Tool Executor
          -> Guardrail / Failure Policy / Trace
      -> Business Services
          -> Weather Provider / Mapper
          -> Rule Engine
          -> Recommendation Engine
          -> Location Comparison
          -> Conversation History
          -> RAG Retriever
      -> Storage
          -> SQLite / SQLAlchemy / Alembic
          -> Redis Session Memory
```

## Agent Runtime

Agent Runtime 由以下模块组成：

- Business Route：识别业务意图，决定请求进入评估、推荐、比选、历史、知识检索或任务单链路。
- Planner：把业务意图拆解成可执行工具调用计划。
- Tool Registry：维护工具名称、能力描述、输入边界和调用入口。
- Tool Executor：按计划执行工具，并把结果写入 Agent State。
- Agent State：保存解析结果、工具输入输出、中间状态、错误和最终响应上下文。
- Failure Policy：对参数缺失、外部依赖失败、工具失败、权限不足、RAG 空召回等场景做分类恢复。

## 业务服务层

业务服务层承接确定性能力：

- 天气服务：地点解析、逐小时天气、天气预警、异常处理。
- 规则引擎：根据任务类型、天气指标、预警信息输出风险等级和规则命中结果。
- 推荐窗口：扫描未来时间段，寻找连续低风险窗口。
- 多地点比选：统一评估多个地点并输出排序依据。
- 历史与会话：保存和查询用户请求、评估记录、会话上下文。
- 任务单：管理任务状态、条件修改和重新计算。

## Guardrail 与 Trace

Guardrail 用于固定安全边界：

- 输入阶段：识别缺失字段、非法请求、越权访问风险。
- 工具阶段：约束工具调用参数，避免越权查询和无效调用。
- 输出阶段：确保最终回复不绕过规则结论、不编造天气或政策依据。

Trace 记录 Agent 执行链路：

- `plan`
- `tool_call`
- `tool_result`
- `error`
- `fallback`
- `final_response`

## Hybrid RAG

RAG 只做解释增强和操作建议补充，不改变规则引擎的安全结论。

当前 RAG 能力包括：

- TF-IDF baseline
- BM25 关键词召回
- Embedding 语义召回
- Hybrid Retrieval
- Metadata filter
- Chunk 策略
- Rerank
- Query rewrite
- 低置信 fallback

## 前端展示关系

前端控制台不做业务安全判断，只展示后端返回结果和执行链路：

- Agent 对话：自然语言入口、结果展示、多轮上下文。
- Trace 面板：展示计划、工具调用、错误、fallback 和最终响应。
- 评估 / 推荐 / 比选页面：展示结构化业务结果。
- 历史 / Profile 页面：展示用户维度数据。
- 管理员页面：展示用户、统计、知识库和会话审计能力。

## 默认运行链路

本地和 Docker 均建议使用 Agent Loop 主链路：

```env
AGENT_RUNTIME_MODE=loop
```

`legacy` 只作为本地兼容模式和 Agent Loop 异常 fallback 路径，不作为 Docker 部署主链路。Docker 默认配置见 [Docker部署说明.md](Docker部署说明.md)。
