# 知识发布与检索维护说明

更新日期：2026-11-27。

## 管理员操作

| 场景 | 操作 | 用户侧行为 |
| --- | --- | --- |
| 新增、补充、普通内容修订 | 保存、审核，再点击“发布知识更新” | 成功发布前继续使用当前已发布版本 |
| 单条知识有误，需要立即停用 | 点击该条知识的“立即撤回” | 该条立即被排除，其余知识继续检索 |
| 修正已撤回的知识 | 编辑修正、启用、审核，再发布 | 发布成功且内容匹配后开放修正版，旧版继续被排除 |
| 整个知识库需要维护 | 点击“暂停全部检索” | 返回维护提示，不提供知识片段或知识操作建议 |
| 全局维护结束 | 管理员点击“恢复全部检索” | 恢复检索，单条撤回和权限限制仍有效 |

保存成功表示修改进入待发布状态。发布失败会保留当前完整版本，不解除紧急撤回，也不会自动恢复全局暂停。权限收紧立即限制访问，扩大权限需要成功发布后生效。

知识检索暂停不停止任务管理、天气获取或规则引擎评估。依赖知识增强的结果不再附带知识片段或操作建议，并显示维护说明。

## 版本发布与并发保护

默认目录为 `data/knowledge/index/`：

```text
current.json                  当前完整版本的发布指针
retrieval-control.json        全局暂停、单条限制和允许使用的修正版
.build.lock                   跨进程构建锁
.control.lock                 管理控制写入锁
versions/
  admin-<唯一标识>/
    source.json               本次构建的知识源快照
    bm25_index.pkl
    bm25_documents.json
    embedding_index.pkl
    embedding_documents.json
    embedding_metadata.json
    tfidf_vectorizer.pkl
    tfidf_matrix.pkl
    documents.json
    manifest.json             来源摘要、文件摘要、关联发布任务
```

发布先在独立版本目录内完成全部构建，再检查文档与源快照是否相符、数量是否对应、Embedding 维度及元数据是否匹配、TF-IDF 矩阵与向量器是否匹配。校验通过后，用同目录临时指针文件和 `os.replace` 切换发布指针。

数据库不再提前记录发布成功。任务先持久保存候选版本和内部阶段，指针切换、访问限制处理结束后，才在同一数据库事务中标记任务成功，并清除与构建修订一致的知识的待发布标记。仅修改发布标记不会改变文档修订时间。

一次默认检索固定一个版本，知识操作建议和 Hybrid 两路检索共用该版本。跨进程查询每次解析发布指针，知识源缓存以解析后的版本路径为键。已发布目录不再由查询原地重建。

显式指定源文件、索引目录的单路 Store，也在独立版本目录内构建，使用各自的 `bm25-current.json`、`embedding-current.json` 或 `tfidf-current.json`。源文件变更触发的自动构建失败时，继续读取来源和模型配置相同的上一有效版本；首次构建无有效版本时返回检索错误。

并发构建返回 HTTP 409，不启动第二个管理员发布任务。Windows 使用系统文件锁，POSIX 使用 `flock`；进程退出后系统释放锁，不依赖手工删除锁文件。

原有平铺文件不再被覆盖。没有发布指针时，默认检索会从当前配置的知识源构建首个完整版本；全新目录在首个版本就绪前没有可回退版本。已有 `KNOWLEDGE_SOURCE_PATH` 显式覆盖仍然优先，使用管理员数据库知识发布时应检查该配置。

## 发布进程退出后的恢复

任务表新增可空字段 `index_version` 和 `publication_phase`，分别保存候选版本和内部阶段。正常阶段为 `building → ready → publishing → completed`；中断且未生效的任务进入 `failed`。对外接口仍沿用 `pending/running/success/failed`，无需改变已有客户端的任务状态枚举。

候选版本的 `manifest.json` 保存发布任务 ID、文档修订时间和构建时的单条限制状态；源文件和索引文件有摘要。恢复不依赖原发布进程的内存。

应用在启动完成数据库迁移后、每次新发布之前，以及运行期间每 60 秒检查中断任务。检查与发布共用构建锁；其他进程持锁时跳过，不能仅凭任务耗时判断其已经退出。周期检查覆盖单个工作进程退出、其他工作进程仍在服务的情况。

| 中断位置或检查结果 | 恢复行为 |
| --- | --- |
| 构建中、构建完成或指针切换前退出 | 任务标为失败，原有待发布标记保留，当前版本继续使用；管理员可重新发布 |
| 指针已切换，但最终数据库事务尚未提交 | 校验对应版本及恢复上下文，补齐成功状态；只清除修订仍匹配的文档标记 |
| 访问限制处理过程中退出 | 依据构建时和当前的限制版本安全补齐；新撤回、权限收紧、全局暂停保持有效 |
| 数据库收尾暂时失败 | 已切换的版本保留，任务维持运行状态，后续恢复重试；管理页面显示正在自动恢复 |
| 候选文件或恢复上下文损坏 | 不激活候选、不自动回滚指针，记录校验失败；如果当前版本本身损坏，需检查文件或重新发布 |
| 任务已完成恢复 | 再次检查不重复改变状态 |

恢复不会自动续发一个尚未切换的候选版本。发布后产生的新编辑仍待发布；解除限制只能开放相符的新版本，不能重新开放撤回的旧版本。控制文件写入失败时保守保留限制，任务附带警告，管理员可重新发布。

升级前的记录没有发布阶段。恢复只针对最新成功任务：若它就是当前版本，补齐关联字段；若能唯一关联候选版本，并确认当前仍是更早的发布，则将这次中断任务改为失败、恢复候选源中知识的待发布状态。该候选源丢失或损坏时，保守将所有知识标为待发布。正常被后续版本替代的历史成功任务不会被判为失败。无法确认关联时不会猜测切换版本，需检查记录并重新发布。

本次新增 Alembic 迁移 `e3b7a9d20c64`。默认启动迁移会应用它；若配置 `AUTO_MIGRATE_ON_STARTUP=false`，部署时须先执行 `python -m alembic upgrade head`。所有工作进程应使用相同代码及共享索引卷。本次没有修改正在运行的业务数据库或部署服务。

## 紧急撤回与权限

紧急限制独立保存在 `retrieval-control.json`，随索引卷共享并持久保存。查询在候选筛选、相关性复核之后和 Agent 返回前检查限制；已经生成的解释若使用了后来撤回的片段，会丢弃该解释并重新使用不含撤回知识的规则模板。

启用已撤回知识后，限制仍保留。发布只能为本次实际构建、内容匹配且构建期间限制未被修改的知识解除限制。修正版使用版本白名单，仍持有撤回旧版本的查询不能因修正版发布而重新返回旧内容。

管理修改先收紧文件控制，再提交数据库。如果数据库提交失败，限制保守保留。后续发布只有在构建内容与管理员期望内容匹配时才可能解除对应限制。管理员可修正数据，重新明确启用、审核并发布。

已经发送给用户的历史内容不会被追回。这里的限制覆盖新的检索输出和仍在处理中的回答；历史会话、历史快照的保存与访问策略不在本次改动范围内。

## 接口与权限

以下接口要求管理员身份：

- `GET /admin/knowledge/retrieval-control`：查询全局状态、当前发布版本、撤回条数和最近控制修改人。
- `PUT /admin/knowledge/retrieval-control`：设置 `paused`，可附带最长 300 字的 `message`。
- `POST /admin/knowledge/reindex`：构建、校验并发布新版本；不修改全局暂停开关。
- 原有知识修改、状态更新和软删除接口：禁用、撤回审核和权限收紧立即限制旧索引中的对应知识。

暂停期间知识检索返回 `retrieval_status=maintenance`，并返回空 `snippets`、空 `advice` 和管理员设置的提示。索引异常继续返回 `error`，没有适用知识继续返回 `fallback`。

## 运维与验收边界

同一实例的所有应用进程必须共享同一个可写索引目录，包括版本目录、指针、控制文件和锁文件。独立文件系统的多副本不能依靠本地锁协调，需要共享存储或另外实现统一发布控制。本次没有部署 Kubernetes 或迁移索引后端。

旧版本和构建失败的目录保留，以保护在途查询并方便排查；本次没有自动清理。只有确认所有相关进程都不再使用某个旧版本后才能清理，不能按固定的短延迟直接删除旧目录。发布指针表示实际生效版本，数据库任务记录辅助审计；两者不是跨数据库和文件系统的单一事务。

2026-11-26 的版本化发布验收见 [原验收记录](evidence/knowledge-publication-20261126/README.md)；2026-11-27 的进程退出恢复与数据库迁移验收见 [恢复验收记录](evidence/knowledge-publication-recovery-20261127/README.md)。测试使用隔离数据库、独立索引和本地模型边界，不代表真实模型效果、生产请求成功率或生产延迟。进程退出恢复不等同于宿主机断电或存储损坏后的完整灾难恢复。
