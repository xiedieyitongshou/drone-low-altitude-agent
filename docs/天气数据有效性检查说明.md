# 天气数据有效性检查

更新日期：2026-11-22。

本轮为现有和风天气 72 小时预报链路增加数据检查。检查通过后才执行规则判断；数据缺失或异常时返回“无法完成评估”，不产生适飞、慎飞或禁飞结论。

## 必需数据与检查范围

当前四类任务规则都使用以下六项：

| 字段 | 含义 | 本项目校验 |
| --- | --- | --- |
| `text` | 天气现象 | 必须非空 |
| `wind_speed` | 风速，沿用现有 v7 接入的 km/h | 有限非负数 |
| `wind_scale` | 风力等级或范围 | 0–17 的整数，或下限不大于上限的范围 |
| `precip` | 降水量 | 有限非负数 |
| `pop` | 降水概率 | 0–100 的有限数 |
| `humidity` | 相对湿度 | 0–100 的有限数 |

缺失、空白、无法解析、NaN、无穷大、负数和超出上述范围的数值都会阻止评估。零值合法。温度、气压、云量当前不参与规则判断，缺失不拦截；不把缺失指标自动补成零。

字段和单位沿用项目已有的 [和风城市小时预报 v7](https://dev.qweather.com/docs/api/weather/weather-hourly-forecast-webapi-v7/) 接入，本轮不切换天气源或 API 版本。

## 时段覆盖

每条小时记录覆盖 `[fx_time, fx_time + 1 小时)`。单地点评估要求这些区间完整覆盖用户请求，包含跨天、非整点和不同时区表示的情况。缺少开头、中间或结尾的任一段均明确报错；重复时间不能补足缺失小时。

未带时区的请求按地点时区解释；地点未提供时区时沿用预报时间的时区偏移。已带时区的请求按其实际时间比较，不因应用运行在上海时区而改变所选地点的当地时间。

只检查本次使用的小时，不要求整个 72 小时响应的业务指标都完整。例如请求 14:00–17:00，只需要涉及该时段的记录；20:00 的指标缺失不阻止本次判断。时间戳本身无法解析时不能确定记录所属时段，因此报告数据异常。

推荐中的 `scan_hours` 沿用最大扫描条数的含义，检查实际返回并参与扫描的连续小时，以及是否至少足够构成 `min_window_hours`。不会把默认 72 解释为必须另有完整 72 小时数据。比选使用每个地点相同的请求时段检查，失败地点保留原因，不进入推荐候选；全部失败时推荐为空。

## 报错契约

| 错误码 | 含义 | 结构化接口 HTTP 状态 |
| --- | --- | --- |
| `WEATHER_DATA_INCOMPLETE` | 空天气、必需指标缺失或时段不完整 | 502 |
| `WEATHER_DATA_INVALID` | 必需指标数值、时间格式或重复时间异常 | 502 |
| `WEATHER_FORECAST_OUT_OF_RANGE` | 有预报，但未覆盖请求时段/日期 | 422 |

错误响应包含 `success=false`、`error_code`、中文 `message`、逐项 `details` 和 `retryable`，不包含评估结论。超出范围提示调整日期或时间，不将原条件下再次点击重试视为可恢复；数据缺失可稍后重新获取。

来源不可用、鉴权错误和响应格式错误继续使用现有天气异常机制。Agent 会明确本次未完成评估，天气或预警请求失败都不会以“无风险/无预警”替代。已有天气 HTTP 客户端负责有限重试，Agent 当前轮保持 `fail_fast`，不整轮回退重放；`retryable` 表示允许客户端发起新请求，不表示自动再次执行。

## 条件保留与 Trace

带 Session 的 Agent 天气失败请求会保留完整条件到 `pending_task`，同时保留此前完成请求的上下文。用户在同一会话输入“重试”或“再试一次”，重新获取天气并重新评估。失败草稿优先于此前成功的地点和时间；成功后清除草稿并保存新上下文。规则解析不再把这些重试指令当作地点。

这是保留输入后重试，不恢复程序调用栈，也不自动重建任务。没有 Session 时，前端原输入/表单仍可直接再次提交。保存重试条件本身失败时返回警告，不掩盖原始天气错误。

Agent 返回的失败结果和可查询 Trace 保留错误码、工具输入、错误信息及数据问题明细。新一次重试有新的 Trace。天气失败不创建成功评估快照、不覆盖历史成功结果，也不更新任务单的最新评估指针或业务状态；失败对话和 Trace 仍可单独记录。
